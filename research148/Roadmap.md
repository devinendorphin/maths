[participation principles](../projects/certified-allocation/Participation.md)
remain the objective: affordable, inspectable and certified allocations as needs
and resources change. The larger inquiry is underway, with bounded results.

The next bounded inquiry should implement a credited specialist incremental
baseline using OR-Tools GenericMinCostFlow or another implementation whose actual
warm state and mutation semantics are inspected. Do not substitute the Simple
Python wrapper: its Solve constructs a fresh optimizer. Generic SetArcCapacity
can change residual flow/excess after reductions; SetNodeSupply directly writes
node excess and needs an inspected adaptation for updates to absolute supplies.
Freeze that adaptation, statuses and guard limits after development tests and
before fresh held-out streams. Compare genuine cost/capacity/need changes against
native cold, retained primal repair and certificate admission, charging every
failed warm attempt, rebuild and proof completion.

That comparison should address the observed bottleneck: exact residual proof
completion and naive cancellation on cyclic graphs. Include ties, negative
cycles, parallel/self-loop arcs, lower-bound transforms, cuts and recovery, and
audit the actual retained state instead of inferring reuse from repeated calls.
Use longer complete sessions or larger families only after the correct state
update contract is established. The current finite comparisons cannot rank
production solvers or justify a claim that reuse is always beneficial.

Retained dual/tree repair for noncost changes remains a distinct possible route.
The current stage retains primal flow; a repaired arbitrary flow need not be a
valid network-simplex basic tree. Any future tree adapter must demonstrate its
feasibility/strong-feasibility invariants and charge repairs and resets.

The application track requires a concrete consenting group, named resources,
eligibility, service floors and priorities. No such group is supplied here;
synthetic balanced supplies do not stand in for human needs or policy agreement.
Continue mathematical work while keeping real allocation and consent decisions
with the affected people. No deployment or merge is authorized by these results.

Source priority review remains open beyond the inspected implementation methods.
Externally trusted anchors, authenticated complete deltas and power-loss-safe
persistence also remain separate requirements if a real application needs them.
