# Assurance for experiments 121–130

The original feasible set is binary knapsack with fixed positive integer weights and capacity. Objective coefficients are `p[j] + t*v[j]` for exact rational `t`; point producers use the equivalent integer coefficients `denominator*p + numerator*v`. Answer stability, applicability of evidence, and complete maintenance cost are reported separately.

Every accepted point fact is independently bound to its original model, rational observation, feasible packing and exact optimum by a separate subset-enumeration auditor. CP formulas are checked against the original signed minimization objective and capacity; auxiliary solution assignments are expanded by the disclosed recovered adaptation. Native and exact-SCIP VIPR headers are checked for original integrality, bounds, capacity, variable mapping and positive objective normalization. External checkers replay each distinct accepted proof and reject a strictly stronger false bound. Hashes establish identity, not mathematical validity.

Interval admission uses a candidate packing optimal at both endpoints. Feasibility is fixed and all competitor objective differences are affine, so endpoint inequalities imply the intervening inequalities. A proof's own point objective does not become a certificate for every interior objective; the independently checked endpoint facts plus this implication justify reuse. Positive-factor admission instead uses an exact common positive scaling. The rational endpoint implication was Lean-checked in experiments 96–100. The new Python hull, admission, policy and cache code is not formally verified.

Immutable admission captures checked facts. It does not watch external proof files, arbitrary dependency changes or running code. The guarded route checks relevant file hashes, headers and endpoint values on each observation after initial external proof admission; it does not replay the entire external proof each time. These assurance contracts differ. Explicit refresh checks the existing hash first, then checks newly declared bytes with the external checker. Unsupported continuous or nonlinear models are rejected; supported capacity, weight and affine-objective changes receive new point certificates. Dependency invalidation tests declared, actual checker deployment changes. It is not an arbitrary code-change detector.

The CP checker fork parent imports official VeriPB code but never checks a proof. Each request gets a fresh child, including interleaved false and malformed controls; child mutations cannot affect the pristine parent. This amortizes deployment startup, not logical proof checking. Parent import, IPC, shutdown and child CPU are charged, with child CPU counted once. This VeriPB deployment uses the unchanged official optimized core and interpreted checking rules, distinct from the recovered historical fifteen-extension installation.

Exact SCIP certificates here come from the actual exact-mode CLI deployment, with presolving/separation disabled in the frozen configuration. Official completion work is charged when required. They are not ordinary SCIP answers certified by a different native solver. Exact SCIP reoptimization remains an unsupported feature of this pinned deployment, established in the preceding repair, and is not attempted or claimed here.

Each method boundary includes construction, required child CPU, proof/input/output I/O, checking, admission, curve discovery, lookup and failed preparation/probes/fallback. Imports before that boundary, SDK installation, common campaign logging, independent auditing and packaging are separate. The complete parent plus waited-child CPU is primary; disjoint phases and residual are retained. CP optimization and proof writing happen together and are not falsely separated. Training is disclosed separately; the frozen policy is reused in fresh replication, not retuned.

Cache budgets apply to retained proof/formula buffers plus serialized fact bytes. Reachable Python bytes, whole-scenario tracemalloc measurements, and sampled simultaneous process-tree RSS are distinct quantities. The memory worker observes unmodified child exits through PPid discovery. Short-lived processes can escape the 2ms sampler; sampled RSS can double-count shared pages and is not a guaranteed peak. Memory-worker observer overhead is charged within that worker and excluded from timing comparisons.
