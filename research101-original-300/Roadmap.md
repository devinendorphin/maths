# Frozen roadmap: experiments 101–110

The next batch follows the finding that repeated witness admission adds cost without improving the mathematical endpoint guarantee. It also addresses the previously unimplemented certifying-DP and production-solver comparisons. Forty input records use eight distinct small mathematical models; repeated observation patterns are explicitly matched.

| Experiment | Question | Declared comparison |
|---|---|---|
| 101 | How does published proof-producing DP compare with our native point proof route? | CP 2024 state/dominance algorithm, independently checked by VeriPB, versus native/VIPR on the same signed point objectives. |
| 102 | Which production features actually work in this installed SCIP build? | Fresh exact-feature probe plus ordinary SCIP proposals admitted only after independent native/VIPR checking. Unsupported exact mode stays explicit. |
| 103 | Does retaining production solver state help after objective changes? | Cold native proof route, cold SCIP plus proofs, and SCIP reoptimization plus the same independent proofs. |

| 105 | Can admission work safely be paid once? | Guarded and factor baselines, repeated witness admission, and immutable admitted endpoint facts on matched dense/sparse streams. |
| 106 | What does the immutable contract reject or intentionally preserve? | Changed models, domains, times and dependency epochs reject; later disk/diagnostic changes do not alter already captured facts. |
| 107 | Does local lookahead avoid unnecessary whole-curve preparation? | Independently checked points, full snapshots, factor baseline, and two fixed local interval widths, charging failed/unused probes. |

The frozen protocol specifies caps and accounting. Candidate generation, proof construction and external checker child CPU are charged. Dependency deployment, source development and independent audit are recorded separately. Three timing repetitions use rotated method order; feature, invalidation and interruption controls use one worker each.

The current PySCIPOpt 6.0.0 wheel embeds SCIP 10.0.0 without exact support. We do not infer that SCIP generally lacks exact solving. Its ordinary proposals are certified by the separate native/VIPR route; this still incurs native solving work and is not production SCIP proof logging.

The published CP algorithm needs supplied-input and signed-profit serialization/big-M adaptations. Its solution logger also receives explicit auxiliary assignments so the pinned VeriPB v2 checker can verify the whole assignment. All transformations are recorded and the final proofs are checked; this is an adaptation of the baseline, not an unmodified reproduction or a new algorithm claim.
