# Frozen roadmap: experiments 56–65

These ten bounded comparisons follow the [51–55 findings](../research51/Synthesis.md). Exactness means signed integer affine profits, fixed feasibility, exact rational oracle queries and independently checked answers. No performance tuning uses held cases.

1. **56 — Capacity scaling.** Match two 12-item draws across common weight/capacity factors 1, 16, 256 and 4,096. Compare raw dense DP, gcd-normalized dense DP and exact branch-and-bound. Separate unchanged feasible packings from changes in numeric representation. Raw allocation failures count as incomplete, not fast solutions.
2. **57 — Item-count scaling.** Compare 12/24/48/64 items at capacity 96 using dense, sparse and B&B parametric oracles. Keep capacities bounded so an independent exact layer checker can audit larger item counts. Repeat the two DP methods on the fixed 24/48-item seed-1 subset.
3. **58 — Integer observations.** Compare the real-parameter envelope recursion with integer-endpoint bisection at H64/H256/H1024, and crafted trajectories with several real pieces between consecutive integers. Count oracle calls, intervals and observed packings; exact integer output does not require discovering every real piece.
4. **59 — Weight gcd.** Test known weight normalization with capacity residuals 0 and g−1, using common factors 16/256. Floor C/g exactly. Compare the same dense oracle before/after normalization; this is an implementation/performance control for a known reduction, not a new theorem.
5. **60 — Dense versus sparse storage.** Test small, gapped and large integer weights at 12/16 items. Compare dense/sparse/B&B methods under prospectively checked allocation and work limits. Report both complete answers and resource boundaries.
6. **61 — Fixed input-only solver choice.** Apply an untrained declared gate: normalize weights; use dense when C<=4,096, sparse when n<=16 otherwise, and B&B for the remaining cases. Charge all features and compare with all three fixed oracles. Best observed CPU is hindsight, not information given to the gate.
7. **62 — Query-cap recovery.** Force primary dense/sparse/B&B queries to stop at one transition/node, then retry normalized dense optimization on small cases. Partial queries remain inactive; charge every attempt and fallback and compare with direct normalized dense optimization.
8. **63 — Full-grid search reuse.** Extend cold/incumbent/terminal-partition B&B to every integer observation, including H256. Compare with point DP and exact parametric DP. Force two later terminal-output caps and retry cold. This remains a controlled exact implementation: production SCIP is unavailable.
9. **64 — Larger proof bundles and scope checks.** On four large-weight 12-item trajectories, independently run the pinned VIPR checker on point controls and endpoints of up to two curve pieces per case. Reject deliberately false final bounds and explicit requests that violate constant feasibility, affine objectives or equal-packing endpoint assumptions.
10. **65 — Transfer.** Transfer the frozen solver gate and integer bisection to fresh 16/24/40-item cases and H256/H1024, including large weights and power slopes. Compare with normalized dense real-curve optimization. Count all integer answers and report caps without treating missing answers as wins.

`Inputs.json` records every row and timing-subset flag. Common scaling/horizon variants are dependent views, not independent draws. Three repeats rotate method order over fixed subsets. Complete repeats must agree logically; physically timed/capped runs are censored in speed comparisons. State counts are memory proxies, not peak-RSS measurements.

`Protocol.json` specifies exact caps, tie rules, accounting and worker counts. Sources and inputs are sealed in `Freeze.json`. Detailed evidence and pinned dependencies go to the verified Drive archive; sources, summary records and receipts stay compact in GitHub.
