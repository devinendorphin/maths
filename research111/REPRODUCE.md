# Evidence recovery and reproduction

The historical original 300-worker archive is now available separately at `archives/experiments-101-110-original-300-workers.tar.xz`. Its source and original deployment recovery instructions are in `research101-original-300/REPRODUCE.md`; the newer verification and separately identified checker replay are explained in [Recovery-followup.md](Recovery-followup.md). Earlier missing-archive statements below describe the pre-recovery state. Do not substitute one batch's archive for another.

The provisional continuation is stored in `archives/experiments-111-120-complete.tar.xz`; [Archive-storage.json](Archive-storage.json) gives its size, checksum and member manifest. Its root members are `headline/` and `replication/`. The separate repair archive and manifest are identified by `repairs/Archive-storage.json`; it has the same two run roots and a `reports/` root. Do not mix those roots or the published 101–110 archive. The missing historical archive's expected identity is in Alignment.md; none of these archives is that archive.

Run `python3 research111/repairs/code/verify_publication.py` from the repository to check compact file identities and read/hash every evidence archive member. It does not rerun mathematics or modify prior evidence. Extract only after checksum/member verification, into a new directory outside the checkout, using Python `tarfile.extractall(..., filter='data')` or an equivalent safe extraction. The repair's `Freeze.json` and `Memory-freeze.json` verify the source/input/dependency files used in its two stages.

Independent audit replay needs Python 3.12+, the retained inherited VIPR binary and its GMP dependencies. Extract the repair archive, then run `python3 code/audit_memory.py` in each run root. It imports no solver/cache/campaign. It recreates false-bound controls and checks original-model subset optima, encoded constraints and positive objective normalization. `audit_integrity.py` additionally requires the exact SDK binary paths from SDK-manifest.json to check deployments. The initially frozen `audit.py` intentionally fails its tree-memory coverage assertion in the recorded runtime; the amendment explains that failure. Do not silently replace it or describe it as having passed.

Experimental reruns require the separately retained `/workspace/maths-toolchains/repair-sdk` and PySCIPOpt 6.0.0 with SCIP 10.0.0 in `/workspace/maths-toolchains/scip-venv`. Use that venv's Python for `campaign.py`; ordinary system Python may not have PySCIPOpt. Confirm binary/source hashes in SDK-manifest.json before claiming identical deployment. Exact SCIP reoptimization is unsupported; the ordinary wheel handles the separate reoptimization comparison.

To reconstruct an absent SDK, retain signed APT/TLS verification and follow the commands in `Exact-setup.json`, `Completion-setup.json` and development logs. Debian 13 prerequisites include GMP/zlib and C++/CMake tooling. Official source pins: SCIP v10.0.0 `0c80fdd8e91d7d9f23c0c7a55b68884209d5f27c`, SoPlex v8.0.0 `2207cfb274dbce5c2644911dd621438535733607`, VIPR `30f2951d1e90e47afa821bdd1b12b82246656c42`. Clone through HTTPS, check each commit, locally extract signed/hash-verified MPFR/Boost packages, then follow `setup_exact.py`. The script expects the pinned SCIP source at `/workspace/maths-toolchains/scip-v10.0.0` and CMake on the scip-venv PATH. Completion requires a compatible CMake 3.31.6 at SDK/checker-venv/bin/cmake, the pinned VIPR source at SDK/vipr-current, and the TBB archive hash recorded in Protocol.json. These setup scripts were tested in this instance with those prerequisites already available; this publication does not claim a new clean SDK installation.

Compile the adapters from an extracted run's `code/` sources with `g++ -O2 -std=c++17 code/vipr_fork.cpp -lgmpxx -lgmp -o /workspace/maths-toolchains/repair-sdk/vipr_fork` and the same command for `vipr_hold.cpp`/`vipr_hold`. They include the unchanged inherited checker source using relative paths. Binary identity can differ with compiler/system changes; report that difference rather than editing frozen expected hashes.

For a new identical-deployment run, copy only the frozen input/source/dependency files and Freeze.json to a fresh directory, verify hashes, run the venv Python on `code/campaign.py`, then copy the separately frozen memory files and run `code/memory_repair.py` and `code/audit_memory.py`. Preserve outputs from each directory. Compare every `kind`/`logical` value exactly, raw and completed proof bytes separately, and retain measurements separately as specified in Replication.json. The memory supplement requires Linux `/proc` status and smaps_rollup access. It measures a retained-state checker checkpoint, not the unmodified campaign peak.

Reports such as Summary.json, Replication.json and the archive/member receipts are post-run products. They do not retroactively enter the pre-run freeze. Preserve original evidence if a rerun disagrees.
